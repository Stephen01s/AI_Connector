# Sprint 1 User Stories

1. As a student, I want to choose two AI models so I can compare how they interact.

2. As a student, I want to assign roles to the two AI models so I can control how they participate in the conversation.

3. As a student, I want to enter an initial prompt so I can give the models a topic or task to discuss.

4. As a student, I want to set a turn limit so the conversation does not continue indefinitely.

5. As a student, I want to watch the models exchange messages so I can observe their interaction.

6. As a student, I want to stop a conversation so I remain in control of the experiment.

7. As a student, I want to review the completed transcript so I can examine the conversation afterward.

8. As a student, I want to save or export a conversation so I can keep a record of my experiment.

# Sprint 1 Acceptance Criteria

* The user can select or configure Model A and Model B.
* The user can assign a role to each model.
* The user can enter an initial prompt.
* The user can choose a turn limit between 1 and 20 turns.
* Model A and Model B alternate responses during a run.
* The conversation stops when the turn limit is reached.
* The user can stop a run before the turn limit is reached.
* The completed conversation can be reviewed as a transcript.
* A run can be saved locally.
* A run can be exported as JSON.
* The user can delete a saved run.
* The application clearly identifies the participants as AI/model simulations.
* The application can run using mock models without requiring external API keys.

# Basic Safety Requirements

* Conversations must have a maximum turn limit.
* The user must be able to stop a conversation.
* Model responses should have a reasonable output limit.
* The interface should make it clear when content is generated by an AI model or mock model.
* The system should not claim that an AI model is conscious, human, or capable of having human experiences.
* API keys and other provider secrets must not be stored in browser-side code.
* Hidden reasoning or chain-of-thought should not be collected or displayed.
* Test conversations should use fictional or non-sensitive information.
* Users should be able to delete saved conversation data.
